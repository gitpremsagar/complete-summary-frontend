<Section id="skills" title="7 skill buckets">
<h3>1. Python और software engineering</h3>
<ul>
  <li><b>Python</b> में सच में अच्छे बनें: functions, classes, data structures, error handling, APIs और third-party libraries के साथ काम करना।</li>
  <li>साथ में engineering basics सीखें: <b>project structure, Git, virtual environments, config files, tests और command line</b>।</li>
  <li>Back-end expert बनने की ज़रूरत नहीं। अपने personal projects के लिए वो <b>Supabase</b> (Postgres, auth, APIs, storage) use करती हैं।</li>
  <li><b>AI के साथ coding का tip:</b> tools किसी model के training data से तेज़ी से बदलते हैं। अपने coding agent को <b>skills</b> दें (सादे markdown instructions) जो उसे live docs check करवाएँ। Skill के बिना Claude Code ने कहा कि schema में कोई performance issue नहीं है; Supabase skill के साथ उसने कई issues पकड़े।</li>
</ul>
<h3>2. Math</h3>
<p>जितना आप सोचते हैं उससे बहुत कम। <b>Linear algebra, probability, statistics और calculus</b> के basics को intuition के रूप में समझें। "आपको कभी भी हाथ से calculation नहीं करनी पड़ेगी, I promise you।"</p>
<h3>3. Machine learning fundamentals</h3>
<p>आप scratch से models train नहीं करेंगे, लेकिन ये चीज़ें फिर भी आती हैं: <b>supervised vs unsupervised learning, training और test sets, overfitting और underfitting, precision और recall</b>, साथ में high level पर neural networks और <b>transformers</b>। Goal है models में फ़र्क समझना और सही model चुनना।</p>
<h3>4. AI engineering fundamentals</h3>
<ul>
  <li><b>LLMs:</b> major models को जानें और <b>performance, cost, speed और licensing</b> के आधार पर चुनें।</li>
  <li><b>Prompt engineering</b>, सही तरीके से: few-shot prompting, structured outputs, defensive prompting, और <b>systematically test करना</b> कि changes से सच में फ़ायदा हुआ या नहीं।</li>
  <li><b>Context engineering:</b> तय करना कि model क्या देखेगा और जब बहुत ज़्यादा information हो तो क्या छोड़ा जाएगा।</li>
  <li><b>RAG (retrieval-augmented generation):</b> model को उसके training set के बाहर का data use करने देना, जैसे internal docs। इसमें embeddings, chunking, vector databases और retrieval आते हैं।</li>
  <li><b>Evaluation:</b> test sets, सही metrics, LLM-as-judge और human evaluation।</li>
</ul>
<h3>5. AI agents</h3>
<p>Agent एक ऐसा LLM है जो <b>functions call कर सकता है और task पूरा होने तक action लेता रहता है</b>: web search, database query, API call, code चलाना। <b>Tool calling</b> सीखें, task completion को evaluate करना सीखें, external tools और data से जुड़ने के लिए <b>MCP (Model Context Protocol)</b>, और आगे चलकर <b>multi-agent systems</b>। हाल में यही area सबसे ज़्यादा बदला है।</p>
<h3>6. Production engineering और infrastructure</h3>
<p>आपके laptop पर चलना और real users को handle करना एक बात नहीं है। <b>APIs, cloud platforms, Docker, basic CI/CD, monitoring और logging</b> सीखें। वो इसे सबसे important buckets में से एक मानती हैं, क्योंकि यही एक demo को ऐसी चीज़ में बदलता है जिसे लोग use कर सकें।</p>
<h3>7. Interview prep</h3>
<ul>
  <li>Job करना और interview pass करना दो अलग skills हैं।</li>
  <li><b>Coding:</b> data structures और algorithms, Python में LeetCode-style problems।</li>
  <li><b>Gen AI system design:</b> "Twitter design करो" की जगह "एक RAG system design करो" या "एक customer support agent design करो" जो scale पर काम करे, ऐसे सवाल expect करें।</li>
</ul>
<Warn><b>Interview prep अभी से, साथ-साथ शुरू करें</b>वरना आप महीनों AI engineering में अच्छे होते रहेंगे और फिर भी असली interview के लिए बिल्कुल तैयार नहीं होंगे।</Warn>

<Section id="first-project" title="आपका पहला project: बिल्कुल simple">

  <li>इसका काम है आपको दिखाना कि आप असल में क्या समझते हैं और क्या review करना है।</li>
  <li>कुछ <b>personal और छोटा</b> चुनें ताकि पहला version जल्दी चल जाए, जैसे एक bot जो आपकी family recipes के scans से dinner suggest करे, या एक daily news brief।</li>
  <li>Personal connection matter करता है। आप judge कर पाते हैं कि AI अच्छा काम कर रहा है या नहीं, और जब पहले मज़ेदार घंटे debugging में बदलते हैं तब भी आप लगे रहते हैं।</li>
</ul>

<Section id="experience" title="किसी और की problem solve करें">
<p>Companies skills की list hire नहीं करतीं; वो अपनी problems solve करवाने के लिए लोग hire करती हैं। आपके project ने आपकी problem solve की, तो अगला step है किसी और की problem solve करना, hire होने का इंतज़ार किए बिना:</p>
<ul>
  <li>किसी <b>nonprofit</b> के लिए कुछ बनाएँ जो उनका समय बचाए।</li>
  <li>किसी <b>hobby group</b> के लिए tool बनाएँ जिसमें आप पहले से हैं।</li>
  <li>किसी <b>दोस्त के small business</b> का कोई irritating process automate करें।</li>
  <li><b>Open source</b> में contribute करें, experienced लोगों के साथ real problems पर काम करें जो feedback दे सकें।</li>
</ul>
<p>रास्ता बहुत matter नहीं करता। जो matter करता है वो है <b>ऐसी requirements जो आपने नहीं बनाईं, ऐसी constraints जो आपने नहीं चुनीं, और ऐसे लोग जो इसे सच में use करें</b>। सही तरीके से किया जाए तो यह आपके resume पर experience के रूप में जा सकता है। वो AI startup शुरू करने को नहीं कह रहीं; बस अपना experience बनाने में creative बनिए।</p>

<Section id="job" title="जब screeners आपको filter कर दें तब job कैसे पाएँ">
<ul>
  <li>Relevant degree या engineering experience के बिना, आपका resume अक्सर किसी इंसान के देखने से पहले ही filter हो जाएगा। मतलब <b>LinkedIn पर mass-apply करना शायद काम नहीं करेगा</b>।</li>
  <li>Networking का मतलब awkward बड़ी conferences नहीं। इसका मतलब है <b>उन companies के लोगों को जानना जहाँ आप काम करना चाहते हैं</b>।</li>
  <li><b>कुछ companies चुनें।</b> वहाँ के AI engineers, hiring managers या technical लोग ढूँढें जो online post करते हैं, open source में contribute करते हैं, talks देते हैं या कोई और public work है।</li>
  <li><b>एक normal इंसान की तरह engage करें:</b> उनके बनाए किसी चीज़ के बारे में पूछें, उनके काम से जुड़ी कोई useful चीज़ share करें, या अपना बनाया कुछ relevant दिखाएँ।</li>
  <li><b>सीधे referral मत माँगिए।</b> इतना असली relationship बनाएँ कि जब कोई role खुले, तो आप हज़ारों resumes के ढेर में कोई random नाम न हों।</li>
</ul>

</Section>
